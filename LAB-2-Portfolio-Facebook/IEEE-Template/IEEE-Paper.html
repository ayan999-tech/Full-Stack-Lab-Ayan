Abstract—This paper presents a concise method for structuring a technical web document using semantic HTML and Cascading Style Sheets (CSS). The approach maps common IEEE conference-paper conventions to a responsive document structure while retaining a print-oriented two-column format. The resulting page is lightweight, readable, and suitable for academic demonstration without client-side scripting.

Keywords—HTML, CSS, document structure, academic publishing, responsive layout, web standards

I. INTRODUCTION

Technical documents require clear hierarchy, consistent typography, and predictable spacing. In a conference paper, the presentation must support rapid reading while preserving enough structure for figures, tables, equations, and references. A web implementation can reproduce these requirements when semantic elements are combined with carefully defined print and screen styles.

This document demonstrates a normal-length conference paper layout. The title and author block appear above two balanced columns, while section headings, captions, and citations follow a restrained academic style. The design intentionally avoids decorative user-interface elements so that the content remains the primary focus.

II. DOCUMENT ARCHITECTURE

A. Semantic Structure

HTML provides the logical outline of the document. A header contains the title and author information, the main element contains the paper body, and individual sections provide meaningful grouping. Figure and table elements are used for visual material, while an ordered list is used for references.

The semantic structure improves accessibility because assistive technologies can identify the title, sections, lists, and supporting content. It also makes the document easier to maintain when the paper is revised.

B. Layout Rules

CSS Grid is used to establish two equal-width columns. The column gap is kept narrow to approximate the compact layout commonly used in IEEE conference templates. At smaller viewport widths, the columns collapse into a single readable stream.

  • Use a serif typeface for paper-like text.
  • Keep section headings centered and uppercase.
  • Use restrained spacing so more content fits on each page.
  • Preserve table and figure captions near their content.

III. IMPLEMENTATION

The implementation uses only HTML and internal CSS. No JavaScript is required for the document structure, print formatting, responsive columns, or academic components. The following simplified relation represents the layout model:

Wc = (Wp − G) / 2(1)

where Wc is the width of one column, Wp is the available paper width, and G is the gap between columns. This relationship keeps both columns balanced while allowing the document to adapt to smaller screens.

B. Maintaining the Integrity of the Specifications

The template is intended to create a consistent reading experience. Margins, column widths, line spacing, and type sizes should be changed only when a specific publication requirement demands it. Consistency is particularly important when papers are assembled into a proceedings volume.

IV. RESPONSIVE PRESENTATION

A paper designed for the screen should remain usable on narrow displays. The desktop version preserves the IEEE-like two-column appearance, while the mobile rule changes the document to one column. This transformation does not change the order of the content; it only changes how the reader encounters it.

Print media rules remove the surrounding screen background and return the document to a clean paper surface. The result can be viewed in a browser, printed, or exported to PDF with minimal visual differences.

V. DISCUSSION

The main advantage of this approach is simplicity. A single HTML document can contain the complete paper, and a single internal style sheet can define both screen and print behavior. This makes the result easy to submit, archive, and inspect in an educational setting.

There are also limitations. Browser pagination may differ slightly from desktop publishing software, and automatic citation management is outside the scope of a static document. For formal submission, the final paper should still be checked against the conference's current author instructions.

VI. CONCLUSION

This paper showed how a short IEEE-style document can be represented using HTML and CSS only. Semantic elements provide the structure, CSS Grid provides the two-column composition, and print media rules support a paper-oriented output. The same principles can be extended to longer manuscripts while keeping the code readable and maintainable.
